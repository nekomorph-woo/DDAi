# wok 文档写作风格规范

所有生成文档或结构化内容的 SKILL 和 agent 遵循本规范。适用产物：`_define.md` / `_findings.md` / `design.md` / `_check.md` / `_plan.md` / `_issue.md` / `_review.md` / `_roadmap.md` 等管道文档，以及 finding、洞察分析等结构化内容。

## 核心目标

文档首先是**给人读的**，其次才是给机器解析的。读者是普通开发者或领域用户，不预设其熟悉 wok 内部术语或软件设计黑话。文字部分必须说人话；机器解析依赖的"硬结构"另见下方边界，不在本规范管辖。

## 文风 6 原则

### 1. 写完整句子，不写电报体

每个占位符、每个条目都按"主语 + 谓语 + 完整意思"的完整句填充，不要名词堆砌。

```
❌ 认证模块。JWT。Token 刷新。
✅ 用户认证模块负责登录与令牌刷新，采用 JWT 方案。
```

**理由**：电报体省下的是作者的字，浪费的是读者的脑——读者要自己补全主语和逻辑关系。

### 2. 术语首次出现就解释

内部术语或专业黑话首次出现时，**要么 inline 通俗解释，要么换成通俗词**。不要假设读者懂。

```
❌ 设计锚点：方向性约束
✅ 设计锚点（划定的方向边界——规定"往哪走"，但不规定"怎么走"）
```

**术语处理优先级**：能换通俗词就换（首选）→ 不能换则首次出现 inline 解释 → 高频术语可建文档内术语表。

### 3. section 之间加过渡

每个 `##` 段落开头用 1 句话承上启下，说明这一段和前一段的关系。不要让 section 像数据库表那样并列跳跃。

```
❌ ## 问题 → ## 目标 → ## 非目标（无连接）
✅ ## 目标 开头：基于上述问题，本功能要达成以下三个目标。
```

### 4. 结构化内容前加叙事

表格、bullet 列表、checkbox 块之前，加 1-2 句话说明"这部分在讲什么、读者该关注什么"。不要直接甩结构化数据。

```
❌（直接给一个 5 列表格）
✅ 下表列出 3 个核心模块的职责与依赖关系。重点关注 auth-core 对 api-gateway 的单向依赖。
```

### 5. 简写要展开

缩写、代号、单字母标记首次出现时注明含义。

```
❌ 优先级：P0/P1/P2  复杂度：S/M/L
✅ 优先级：P0（必须做）/ P1（重要）/ P2（可选）
   复杂度：S（简单）/ M（中等）/ L（复杂）
```

### 6. 中文文档用中文词

中文文档里，能翻译的英文术语要翻译；只有业界通用的技术缩写（如 JWT、API、HTTP、URL）可保留原文。

```
❌ 将 PRD 解析为 feature 列表
✅ 将需求文档解析为功能列表
```

## 模板占位符规则

**这是防止电报体的最关键单点。** 模板里的占位符必须给**完整例句**，不要写 `<一句话>` 这种诱导简洁的占位符。

```
❌ <锚点：一句话>
✅ <锚点：完整句子，如"用户登录必须在一次 HTTP 请求内完成，不允许多次往返">
```

例句的作用是示范句式和详细度。生成时**按此句式填充真实内容，不要照抄示例文字**。

## 硬结构边界（本规范不改动）

以下结构是 dashboard 解析或下游 SKILL 消费的依赖，**不属于文风管辖**，改造时保持不变：

- `##` / `###` section 标题文字（解析锚点）
- emoji 标记：`🤖` `👤` `🔴` `🟠` `🟡` `✅` 等严重度/类型标记
- checkbox：`- [ ]` / `- [x]`
- 表格列定义（表头行）
- frontmatter 字段：`status` / `intent` / `scope` / `depends` / `changed` / `freshness` / `wok.*`
- 固定格式标记：`US-N 🤖M`、`[DECISION]` / `[ACTION]` / `[OPEN]`、`## Round N`、`[severity] file:line — title`、`✅ Converged` / `Analyzed` 状态、`<details>` 折叠规则

文风改造只动**这些结构之间的描述性文字**。

## 各 SKILL 内嵌要求

每个生成文档的 SKILL 在 output-format 模板前，内嵌以下精炼 3 条（让 LLM 即使不读本文件也见到核心要求）：

```
> **📝 文风要求**（完整规范见 `skills/_shared/doc-writing-style.md`）：
> 1. 写完整句子，不写电报体——占位符都按例句的完整句式填充，不照抄例句文字
> 2. 术语首次出现就通俗解释，或换通俗词
> 3. section 间加 1 句过渡；表格/bullet 前加 1-2 句"这说明了什么"
```
