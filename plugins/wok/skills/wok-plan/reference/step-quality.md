# 执行步骤质量规范

每个执行步骤必须回答以下 6 个问题。

## 6 项必备要素

### 1. 文件范围

列出这一步涉及的文件：

- 新建文件：完整路径
- 修改文件：完整路径 + 修改区域描述
- **DO NOT** 写"视情况而定" — 必须明确

### 2. 接口清单

列出这一步要实现的接口：

- 从模块 `design.md` 中提取
- 标注哪些接口在这一步实现，哪些留到后续步骤

### 3. 验证标准

每个步骤必须有一个可通过的验证方式：

- 优先：自动化测试（TDD）
- 备选：编译检查、lint、手动验证脚本
- **DO NOT** 写"功能正常" — 必须可观测、可重复

### 4. 集成标注

标注这一步与其他模块的交叉点：

```
集成点: 调用 <模块B>.<接口X>()
前置: <模块B> 的 <接口X> 必须已实现
风险: <如果模块B的接口变更，这里需要同步修改>
```

### 5. 验收标准映射

每个 ACTION step 必须声明它覆盖了哪些验收标准：

```
**覆盖验收标准**: US-1 🤖①, US-2 🤖③
```

- 从 `_define.md` 的 `## 验收标准` section 提取 🤖 条目
- 根据 step 实现的功能，标注该 step 覆盖的 🤖 条目编号
- 所有 🤖 验收标准必须被至少一个 step 覆盖
- CHECKPOINT step 不需要此字段

### 6. 测试覆盖声明

每个 ACTION step 必须声明三层测试覆盖（CHECKPOINT 不需要）：

```
**测试覆盖**：
- 正常路径：<具体行为描述>
- 边界条件：<具体行为描述>
- 异常路径：<具体行为描述>
```

- 三层均为**行为描述**，非实现步骤
- 顶级字段（不折叠进 `<details>`），供 pr-test-analyzer 静态提取核对
- 与第 3 要素"验证标准"的区别：验证标准回答"如何判断完成"（可自动化/编译/lint），测试覆盖回答"必须测试哪些行为"
- wok-execute 按三层逐条 TDD；pr-test-analyzer 对照三层静态核对 impl 测试是否覆盖

## 遗漏风险识别

以下情况容易导致开发遗漏，需要特别标注：

| 风险信号 | 说明 | 应对 |
|----------|------|------|
| 一个步骤涉及 5+ 个文件 | 可能需要拆分 | 考虑拆为 2 个步骤 |
| 集成点无前置步骤 | 依赖模块还没做 | 调整执行顺序 |
| 验证标准不可自动化 | 依赖人工判断 | 考虑补充测试用例 |
| 步骤间有隐式依赖 | 步骤 B 需要步骤 A 的内部状态 | 显式标注依赖 |
