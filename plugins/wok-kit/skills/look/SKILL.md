# look

定向探索用户指定的目标区域，建立结构化理解后口头汇报。仅供后续讨论使用，不落盘。

目标可以是代码模块、SKILL 目录、配置文件、设计文档等任意类型。

## 深度级别

用户关键词指定深度，未指定则默认 medium。

| 级别 | 触发词 | 行为 |
|------|--------|------|
| quick | quick / 快速 / 扫一眼 | 读关键入口文件 + 核心类型/接口/配置，概览级别 |
| medium | （默认） | quick + 追踪核心流程 + 关键关系 + 识别设计模式/组织方式 |
| deep | deep / 深度 / 仔细 | medium + 全面追踪依赖 + 边界条件 + 隐含假设 + 潜在问题和改进空间 |

## 流程

### 1. 确认目标

用户描述模糊时澄清后再开始：

- 具体路径或目标名
- 探索意图（想了解什么、后续讨论什么话题）

### 2. 定向探索

按指定深度使用 Read、Glob、Grep 读取和分析目标区域。

探索前先判断目标类型，选用合适的分析视角。

### 3. 口头汇报

按以下结构输出。**禁止写入任何文件。**

#### 职责

一句话说明目标区域解决什么问题、承担什么角色。

#### 结构

目标区域内关键文件/子目录清单，各自承担什么角色，彼此什么关系。

#### 关键路径

按目标类型自适应：

| 目标类型 | 回答的问题 |
|----------|-----------|
| 代码模块 | 核心调用链和数据流，2~5 步关键节点 |
| SKILL / 规则 / 文档 | 触发条件 → 执行流程 → 输出结果，关键步骤 |
| 配置 / 资源 | 被谁引用、影响什么行为、变更影响范围 |

#### 特征与约定

- 组织模式、命名风格、隐含假设、关键设计决策
- 与同类目标的共性和差异（有参照物时）

#### 值得注意的点

（quick 跳过本节）

- 欠清晰处、潜在矛盾、技术债务
- 可优化点，不展开方案，只标位置

#### 就绪确认

一句话宣告探索完成，等待后续指令。格式自由，如"这部分理解了，聊什么？"

## 反模式

- **落盘**：禁止写入任何文件到磁盘。仅供当前对话使用。
- **越界**：探索范围限定用户指定的目标区域，不扩展到无关模块。
- **论文**：每节控制在必要长度内。汇报是摘要不是文档。
